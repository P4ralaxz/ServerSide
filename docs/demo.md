### 0.2 เริ่มระบบด้วยข้อมูลเดโมชุดใหม่ + เปิด tunnel

```bash
docker compose up -d
npm run migration:run
npm run seed -- 67070017@kmitl.ac.th 67070053@kmitl.ac.th 67070097@kmitl.ac.th
```

แล้วเปิด ngrok ชี้ไปที่ `API_PORT` — ลิงก์ ngrok ใช้ได้ทั้งคนคุมจอและอาจารย์ (`TRUST_PROXY=true`, `APP_BASE_URL` = ลิงก์ ngrok ให้ QR ชี้ถูกที่)

`npm run seed` **ล้างข้อมูลทั้งหมด** แล้วสร้างบัญชีทีมใหม่ทั้งชุด — seed ใหม่ได้ทุกครั้งที่ซ้อม
บัญชีอีเมลเปล่าของแต่ละคน (เช่น `67070017@kmitl.ac.th`) ไม่ถูกสร้าง — ถ้าต้องการ รัน `npm run user:make-admin -- <อีเมล>` หลัง seed
`.env` ต้องส่งเมลจริง (SMTP ของ Gmail ตามที่ตั้งไว้) — ไม่ใช้ Mailpit

### 0.3 เปิดหน้าต่างไว้ล่วงหน้า — login ทุกบัญชีก่อนเริ่ม

sessionStorage แยกต่อแท็บ — **แท็บละบัญชี** login ค้างไว้ได้หลายบทบาทในเบราว์เซอร์เดียว (token อยู่ได้ 8 ชม.)
login ล่วงหน้าทุกแท็บ **ยกเว้นแท็บ A** — ขั้น 2 login สดให้ดูครั้งเดียว

| แท็บ | บัญชี | ขนาดจอ | ใช้ในขั้น |
|---|---|---|---|
| A | (ยังไม่ login → `+student1` ในขั้น 2) | มือถือ (DevTools 360px) | 2, 6, 9 |
| B | `+student2` รูมเมท | มือถือ | 3, 8 |
| C | `+student3` ห้องอื่น | มือถือ | 3, 10 |
| D | `+staff1` | เดสก์ท็อป | 1, 4, 8, 10, 11 |
| E | `+tech1` | มือถือ | 5, 7, 9 |
| H | Swagger `/docs` (Authorize ด้วย token ของ `+admin1`) | เดสก์ท็อป | 3, 12 |
| I | กล่องเมลของคนคุมจอ | เดสก์ท็อป | 2 |

token สำหรับปุ่ม Authorize ของ Swagger: login บัญชีนั้นในแท็บของมันแล้วคัดลอกค่า `token` จาก DevTools → Application →
Session Storage → `dorm.session` (ขั้น 3 ใช้ของ `+student2` และ `+student3` · ขั้น 12 ใช้ของ `+admin1`)

ลิงก์สแกน QR (ขั้น 2, 3, 10): เปิดจากหน้าพิมพ์ QR ขั้น 1 (คลิกขวาที่รูป → เปิดรูป แล้วสแกนจากจอด้วยมือถือ) หรือคัดลอก `/app/scan/<qr_token>`
ของชิ้นนั้นจาก Swagger `GET /assets?room_id=…` (staff เห็น `qr_token`)

## 1. Staff พิมพ์ QR ของห้อง D1-301 (แท็บ D) ⏱

เมนู **พิมพ์ QR** → เลือก **D1 ห้อง 301** → เห็นสติกเกอร์ 8 ชิ้น → กด **พิมพ์ 8 ชิ้น** (เปิดตัวอย่างก่อนพิมพ์ให้ดูแล้วยกเลิก)

ชี้ให้ดู:
- QR เป็นของ **ครุภัณฑ์ทีละชิ้น** ไม่มี QR ระดับห้อง — กฎข้อ 1: 1 ใบ = 1 ครุภัณฑ์
- ลิงก์ใน QR ใช้ `qr_token` สุ่ม 128 บิต ไม่ใช่รหัสครุภัณฑ์ที่ไล่เลขได้ทั้งหอ
- สติกเกอร์ติดไปแล้วแก้ไม่ได้ — ย้ายห้อง / เปลี่ยนชื่อแก้ที่ฐานข้อมูล ไม่ต้องพิมพ์ใหม่

## 2. นักศึกษาสแกน QR แอร์ → login → แจ้งซ่อม (แท็บ A + I)

เปิดลิงก์สแกนของ **D1-301-AC (เครื่องปรับอากาศ)** → ถูกพาไปหน้า login ("คุณสแกน QR ครุภัณฑ์ในหอพัก")
→ อีเมล `67070017+student1@kmitl.ac.th` → **ส่งรหัสทางอีเมล** → เปิดรหัสในกล่องเมล (แท็บ I) → ใส่รหัส
→ กลับมาหน้าสแกนเอง → **แจ้งซ่อมชิ้นนี้** → อาการ "แอร์มีน้ำหยดใส่โต๊ะตอนเปิดเกิน 1 ชั่วโมง" → **ส่งแจ้งซ่อม 1 รายการ** → ได้เลขใบ `TK-2569-…`

ชี้ให้ดู:
- **ไม่มีรหัสผ่าน** — OTP 6 หลัก เก็บเป็น HMAC อายุ 10 นาที ผิดเกิน 5 ครั้งใช้ไม่ได้ (ลองใส่ผิดหนึ่งครั้งให้เห็น "ลองได้อีก 4 ครั้ง")
- JWT มีแค่ `sub` — guard โหลดผู้ใช้จาก DB ทุก request (ระงับบัญชีแล้วมีผลทันที)
- สวิตช์ "ช่างเข้าห้องได้ตอนไม่มีคนอยู่" — ถ้าปิด ช่างต้องนัดก่อนเริ่มงาน

## 3. แจ้งซ้ำไม่ได้ + ห้องอื่นไม่เห็น (แท็บ B, C, H)

- แท็บ B (`+student2` รูมเมท) สแกนแอร์ตัวเดิม → เห็น **เลขใบเดิม** และปุ่ม **เจอปัญหาเดียวกัน** — ไม่มีปุ่ม "แจ้งซ่อมชิ้นนี้"
- แท็บ H (Swagger) `POST /tickets` ชิ้นเดิมด้วย token ของ `+student2` → **409** `DUPLICATE_OPEN_TICKET`
- แท็บ C (`+student3` ห้อง D2-301) สแกนแอร์ตัวเดิม → "แจ้งซ่อมได้เฉพาะผู้พักห้องนั้น" **ไม่เห็นเลขใบ**
- Swagger `POST /tickets` ชิ้นเดิมด้วย token ของ `+student3` → **403** (ไม่ใช่ 409)

ชี้ให้ดู:
- กันแจ้งซ้ำที่ **DB** ด้วย partial unique index `idx_tickets_asset_open` — predicate ตรงกับ `OPEN_STATUSES` มี contract test เทียบ
- ลำดับการตรวจ **role (403) → ownership (403) → state (409)** — ถ้าเช็คซ้ำก่อน ownership คนห้องอื่นจะรู้ว่าห้องนี้แจ้งอะไรไว้ผ่าน 409

## 4. Staff มอบหมายให้ช่าง (แท็บ D)

คิวงาน → ตัวกรอง **รอมอบหมาย** → คลิกใบใหม่ → เลือกช่าง **สมชาย ใจดี** → **มอบหมาย**

ชี้ให้ดู:
- ตัวเลขบนตัวกรองลดลงทันที — มาจาก `GET /tickets/queue-counts` ที่ใช้เงื่อนไขชุดเดียวกับรายการ
- ทุกการเปลี่ยนสถานะ: lock แถว (`pessimistic_write`) + UPDATE + INSERT log ในทรานแซกชันเดียว
- endpoint แยกตามสิทธิ์ (`/assign` `/status` `/confirm` …) ไม่มี `PUT /tickets/:id`

## 5. ช่างเริ่มงาน → ซ่อมเสร็จ (แท็บ E)

งานของฉัน → เปิดใบ → **เริ่มงาน** → **ซ่อมเสร็จ** (บันทึก "ล้างถาดน้ำทิ้งและท่อน้ำทิ้งตัน") → **ยืนยันซ่อมเสร็จ**

ชี้ให้ดู:
- **ช่างปิดงานเองไม่ได้** — ไปได้สูงสุด `resolved` ไม่มีปุ่มปิดใบ และจอบอกว่า "คุณปิดใบเองไม่ได้"
- ปุ่มทุกปุ่มบนจอมาจาก `actions` ที่ API ส่งมา — หน้าจอไม่มีกฎของตัวเอง (contract test ยิงทุกปุ่มทุกบทบาททุกสถานะ)

## 6. ผู้แจ้งกด "ยังไม่หาย" (แท็บ A)

ส่งซ่อมแล้ว → ใบในกลุ่ม **รอคุณยืนยัน** → **ยังไม่หาย** → กดส่งโดยไม่กรอก (โดนบล็อก) → กรอก "เปิดไปสองชั่วโมงน้ำหยดอีก" → **ส่งกลับให้ช่าง**

ชี้ให้ดู:
- ใบกลับไปหา **ช่างคนเดิม** (ไม่ใช่กลับไปรอมอบหมาย) และนับ `reopen_count`
- ถ้าผู้พักไม่ยืนยันภายใน 3 วัน ระบบปิดให้ (ขั้น 12)

## 7. ช่างซ่อมรอบสอง (แท็บ E) ⏱

งานของฉัน → กลุ่ม **ถูกส่งกลับ** อยู่บนสุดพร้อมเหตุผลของผู้พัก → เริ่มงาน → ซ่อมเสร็จ ("เปลี่ยนท่อน้ำทิ้งเส้นใหม่")

## 8. Staff ยืนยันแทนไม่ได้ → รูมเมทปิดใบ (แท็บ D, B)

- แท็บ D: เปิดใบเดิมในคิว → "Staff ยืนยันใบห้องพักแทนไม่ได้" ไม่มีปุ่มยืนยัน
- แท็บ B (`+student2` รูมเมท ไม่ใช่คนแจ้ง): เปิดใบ → **หายแล้ว ปิดใบ** → **ยืนยัน ปิดใบ**

ชี้ให้ดู:
- สิทธิ์ยืนยัน **ผูกกับห้อง ไม่ใช่กับคน** — คนที่พักห้องนั้นตอนนี้ยืนยันได้ (ใบส่วนกลาง Staff เป็นคนยืนยัน)
- admin ⊇ staff แต่ก็ยืนยันใบห้องพักไม่ได้เหมือนกัน

## 9. ใบรออะไหล่ + ความเห็นภายใน (แท็บ E, A)

- แท็บ E: งานของฉัน → กลุ่ม **รออะไหล่** (หลอดไฟเพดาน D1-301 — ห้องของผู้แจ้งเอง) → เปิดใบ → การ์ดความเห็นมี "อะไหล่ราคา 850 บาท…" พื้นสีเหลือง ป้าย **ภายใน**
- แท็บ A (`+student1` ผู้พักห้องนั้น): ส่งซ่อมแล้ว → เปิดใบหลอดไฟ → เห็นแค่ "สั่งหลอดไฟแล้ว…" **ไม่เห็นความเห็นภายใน** และไม่มีสวิตช์ภายใน

ชี้ให้ดู:
- รออะไหล่ต้องบอกชื่ออะไหล่ (`NOTE_REQUIRED`) · รายงานเวลาซ่อมไม่นับช่วงรออะไหล่
- ความเห็นภายในกรองที่ API ด้วยเงื่อนไขเดียว (`TicketPolicy.canSeeInternal`) ทั้งอ่านและเขียน — นักศึกษาส่ง `is_internal` ได้ 403

## 10. คนที่ 11 กดเจอปัญหาเดียวกัน → ด่วนมาก (แท็บ C + D)

- แท็บ D: จำตัวเลขบนตัวกรอง **ด่วนมาก**
- แท็บ C (`+student3`): สแกน QR ของ **D2-CM-G-ELEC (ไฟฟ้าทั่วไป ส่วนกลาง D2)** → ใบนี้มีคนแจ้งแล้ว 10 คน → **เจอปัญหาเดียวกัน**
- แท็บ D: refresh → ตัวกรอง **ด่วนมาก** เพิ่ม 1 · เปิดใบ → คนเจอปัญหา 11 คน + ประวัติ "ยกเป็นด่วนมากอัตโนมัติ"

ชี้ให้ดู:
- 1 คนนับได้ครั้งเดียว (`ticket_reporters` PK) — กดซ้ำได้ 409
- `report_count > 10` → `urgent` **ครั้งเดียวต่อใบ** · audit `auto_escalate` ไม่มีผู้กด (ระบบเป็นคนยก)
- ใบส่วนกลางเปิดให้นักศึกษา **ทุกอาคาร** — คนอาคารไหนก็กดได้ ไม่มีเงื่อนไขอาคารเดียวกัน

## 11. ใบส่วนกลางที่มีคนแย้ง (แท็บ D) ⏱

คิวงาน → ตัวกรอง **มีคนแย้งว่ายังไม่หาย** → ใบเครื่องซักผ้า D2 ที่ช่างบอกว่าซ่อมเสร็จ แต่มีนักศึกษากดเจอปัญหาเดียวกันหลังจากนั้น

ชี้ให้ดู:
- `disputed_at` ถูกตั้งเมื่อมีคนกด same-issue หลัง resolved → **ระบบไม่ปิดเอง** ต้องให้ Staff ตัดสิน

## 12. สั่งรัน job ปิดอัตโนมัติ + รายงาน (แท็บ H + D)

- แท็บ H (Swagger, admin): `POST /admin/jobs/auto-close/run` → `closed_count` ≥ 2 · ใบเครื่องซักผ้าของขั้น 11 **ไม่อยู่ในรายการ**
- แท็บ D: เมนู **รายงาน** → KPI "ระบบปิดให้เมื่อครบ 3 วัน" และแท่ง "ใครเป็นคนปิดใบ" มีช่อง **ระบบปิดให้**

ชี้ให้ดู:
- ใบที่ระบบปิด: `confirmed_by = NULL`, `close_reason = auto_closed` — รายงานแยกจากใบที่มีคนยืนยันจริงได้
- endpoint นี้มีไว้เพราะตอนนำเสนอรอ 3 วันไม่ได้ — ใช้ฟังก์ชันเดียวกับ cron ไม่มีพารามิเตอร์ข้ามเงื่อนไข · staff เรียกไม่ได้ (403)
- รายงานคิดตามเวลาไทย ทุก query มี `deleted_at IS NULL`

## ถ้ามีเวลาเหลือ

- หน้า **ผู้ใช้** (admin): เปลี่ยนบทบาท / ผูกห้อง / ระงับบัญชี — ระงับช่างที่มีงานค้างไม่ได้ (409 พร้อมเลขใบ)
- `/docs` (Swagger): ทุก endpoint มีตัวอย่างและ error code
- `npm run test:e2e` บน Testcontainers (Postgres จริง) + mutation check (DESIGN หัวข้อ 10)

## ถ้าขั้นไหนพัง

- เริ่มใหม่จากขั้น 0.2 (`npm run seed -- …`) — ทุกขั้นใช้ข้อมูลที่ seed สร้างใหม่ทุกครั้งเหมือนเดิม
- รหัส OTP ไม่มา → ดูโฟลเดอร์สแปม / ตรวจ SMTP ด้วย `npm run mail:test -- <อีเมล>` · ขอรหัสอีเมลเดิมได้ทุก 60 วินาที
- ขั้น 10 กดได้ครั้งเดียวต่อการ seed (คนแรกที่กดทำให้เป็นด่วนมาก) — ซ้อมแล้วต้อง seed ใหม่ก่อนวันจริง
