## 0. เตรียมก่อนนำเสนอ (ทำก่อนเข้าห้อง ~10 นาที)

### 0.1 ให้รหัส login ของบัญชีเดโมเข้า Mailpit

บัญชี `demo.*@kmitl.ac.th` ไม่มีกล่องเมลจริง — วันนำเสนอให้ส่งเมลเข้า Mailpit (http://localhost:8026) แทน Gmail
ใน `.env` ใส่ `#` หน้าบรรทัด SMTP ของ Gmail ทุกบรรทัด (`SMTP_HOST` `SMTP_PORT` `SMTP_SECURE` `SMTP_USER` `SMTP_PASS` `MAIL_FROM`)
แล้วเพิ่ม `SMTP_HOST=localhost` — ค่าอื่นใช้ค่าเริ่มต้นที่ชี้ไป Mailpit อยู่แล้ว · จบงานแล้วสลับกลับ

### 0.2 เริ่มระบบด้วยข้อมูลเดโมชุดใหม่

```bash
docker compose up -d
npm run migration:run
npm run seed
npm run web:build
```

`npm run user:make-admin -- <อีเมล>` และ `npm run user:demo -- <อีเมล>` หลัง seed

## 1. Staff พิมพ์ QR ของห้อง D1-303 (แท็บ D) ⏱

เมนู **พิมพ์ QR** → เลือก **D1 ห้อง 303** → เห็นสติกเกอร์ 8 ชิ้น → กด **พิมพ์ 8 ชิ้น** (เปิดตัวอย่างก่อนพิมพ์ให้ดูแล้วยกเลิก)

ชี้ให้ดู:
- QR เป็นของ **ครุภัณฑ์ทีละชิ้น** ไม่มี QR ระดับห้อง — กฎข้อ 1: 1 ใบ = 1 ครุภัณฑ์
- ลิงก์ใน QR ใช้ `qr_token` สุ่ม 128 บิต ไม่ใช่รหัสครุภัณฑ์ที่ไล่เลขได้ทั้งหอ
- สติกเกอร์ติดไปแล้วแก้ไม่ได้ — ย้ายห้อง / เปลี่ยนชื่อแก้ที่ฐานข้อมูล ไม่ต้องพิมพ์ใหม่

## 2. นักศึกษาสแกน QR แอร์ → login → แจ้งซ่อม (แท็บ A + I)

เปิดลิงก์สแกนของ **D1-303-AC (เครื่องปรับอากาศ)** → ถูกพาไปหน้า login ("คุณสแกน QR ครุภัณฑ์ในหอพัก")
→ อีเมล `demo.s0005@kmitl.ac.th` → **ส่งรหัสทางอีเมล** → เปิดรหัสใน Mailpit (แท็บ I) → ใส่รหัส
→ กลับมาหน้าสแกนเอง → **แจ้งซ่อมชิ้นนี้** → อาการ "แอร์มีน้ำหยดใส่โต๊ะตอนเปิดเกิน 1 ชั่วโมง" → **ส่งแจ้งซ่อม 1 รายการ** → ได้เลขใบ `TK-2569-…`

ชี้ให้ดู:
- **ไม่มีรหัสผ่าน** — OTP 6 หลัก เก็บเป็น HMAC อายุ 10 นาที ผิดเกิน 5 ครั้งใช้ไม่ได้ (ลองใส่ผิดหนึ่งครั้งให้เห็น "ลองได้อีก 4 ครั้ง")
- JWT มีแค่ `sub` — guard โหลดผู้ใช้จาก DB ทุก request (ระงับบัญชีแล้วมีผลทันที)
- สวิตช์ "ช่างเข้าห้องได้ตอนไม่มีคนอยู่" — ถ้าปิด ช่างต้องนัดก่อนเริ่มงาน

## 3. แจ้งซ้ำไม่ได้ + ห้องอื่นไม่เห็น (แท็บ B, C, H)

- แท็บ B (`s0006` รูมเมท) สแกนแอร์ตัวเดิม → เห็น **เลขใบเดิม** และปุ่ม **เจอปัญหาเดียวกัน** — ไม่มีปุ่ม "แจ้งซ่อมชิ้นนี้"
- แท็บ H (Swagger) `POST /tickets` ชิ้นเดิมด้วย token ของ `s0006` → **409** `DUPLICATE_OPEN_TICKET`
- แท็บ C (`s0001` ห้อง D1-301) สแกนแอร์ตัวเดิม → "แจ้งซ่อมได้เฉพาะผู้พักห้องนั้น" **ไม่เห็นเลขใบ**
- Swagger `POST /tickets` ชิ้นเดิมด้วย token ของ `s0001` → **403** (ไม่ใช่ 409)

ชี้ให้ดู:
- กันแจ้งซ้ำที่ **DB** ด้วย partial unique index `idx_tickets_asset_open` — predicate ตรงกับ `OPEN_STATUSES` มี contract test เทียบ
- ลำดับการตรวจ **role (403) → ownership (403) → state (409)** — ถ้าเช็คซ้ำก่อน ownership คนห้องอื่นจะรู้ว่าห้องนี้แจ้งอะไรไว้ผ่าน 409

## 4. Staff มอบหมายให้ช่าง (แท็บ D)

คิวงาน → ตัวกรอง **รอมอบหมาย** → คลิกใบใหม่ → เลือกช่าง **สมชาย ใจดี** → **มอบหมาย**

ชี้ให้ดู:
- ตัวเลขบนตัวกรองลดลงทันที — มาจาก `GET /tickets/queue-counts` ที่ใช้เงื่อนไขชุดเดียวกับรายการ
- ทุกการเปลี่ยนสถานะ: lock แถว (`pessimistic_write`) + UPDATE + INSERT log ในทรานแซกชันเดียว
- endpoint แยกตามสิทธิ์ (`/assign` `/status` `/confirm` …) ไม่มี `PUT /tickets/:id`

## 5. ช่างเริ่มงาน → ซ่อมเสร็จ (แท็บ E)

งานของฉัน → เปิดใบ → **เริ่มงาน** → **ซ่อมเสร็จ** (บันทึก "ล้างถาดน้ำทิ้งและท่อน้ำทิ้งตัน") → **ยืนยันซ่อมเสร็จ**

ชี้ให้ดู:
- **ช่างปิดงานเองไม่ได้** — ไปได้สูงสุด `resolved` ไม่มีปุ่มปิดใบ และจอบอกว่า "คุณปิดใบเองไม่ได้"
- ปุ่มทุกปุ่มบนจอมาจาก `actions` ที่ API ส่งมา — หน้าจอไม่มีกฎของตัวเอง (contract test ยิงทุกปุ่มทุกบทบาททุกสถานะ)

## 6. ผู้แจ้งกด "ยังไม่หาย" (แท็บ A)

ส่งซ่อมแล้ว → ใบในกลุ่ม **รอคุณยืนยัน** → **ยังไม่หาย** → กดส่งโดยไม่กรอก (โดนบล็อก) → กรอก "เปิดไปสองชั่วโมงน้ำหยดอีก" → **ส่งกลับให้ช่าง**

ชี้ให้ดู:
- ใบกลับไปหา **ช่างคนเดิม** (ไม่ใช่กลับไปรอมอบหมาย) และนับ `reopen_count`
- ถ้าผู้พักไม่ยืนยันภายใน 3 วัน ระบบปิดให้ (ขั้น 12)

## 7. ช่างซ่อมรอบสอง (แท็บ E) ⏱

งานของฉัน → กลุ่ม **ถูกส่งกลับ** อยู่บนสุดพร้อมเหตุผลของผู้พัก → เริ่มงาน → ซ่อมเสร็จ ("เปลี่ยนท่อน้ำทิ้งเส้นใหม่")

## 8. Staff ยืนยันแทนไม่ได้ → รูมเมทปิดใบ (แท็บ D, B)

- แท็บ D: เปิดใบเดิมในคิว → "Staff ยืนยันใบห้องพักแทนไม่ได้" ไม่มีปุ่มยืนยัน
- แท็บ B (`s0006` รูมเมท ไม่ใช่คนแจ้ง): เปิดใบ → **หายแล้ว ปิดใบ** → **ยืนยัน ปิดใบ**

ชี้ให้ดู:
- สิทธิ์ยืนยัน **ผูกกับห้อง ไม่ใช่กับคน** — คนที่พักห้องนั้นตอนนี้ยืนยันได้ (ใบส่วนกลาง Staff เป็นคนยืนยัน)
- admin ⊇ staff แต่ก็ยืนยันใบห้องพักไม่ได้เหมือนกัน

## 9. ใบรออะไหล่ + ความเห็นภายใน (แท็บ E, F)

- แท็บ E: งานของฉัน → กลุ่ม **รออะไหล่** (ใบหลอดไฟเพดาน D1-302) → เปิดใบ → การ์ดความเห็นมี "อะไหล่ราคา 850 บาท…" พื้นสีเหลือง ป้าย **ภายใน**
- แท็บ F (`s0004` ผู้พักห้องนั้น): เปิดใบเดียวกัน → เห็นแค่ "สั่งอะไหล่แล้ว…" **ไม่เห็นความเห็นภายใน** และไม่มีสวิตช์ภายใน

ชี้ให้ดู:
- รออะไหล่ต้องบอกชื่ออะไหล่ (`NOTE_REQUIRED`) · รายงานเวลาซ่อมไม่นับช่วงรออะไหล่
- ความเห็นภายในกรองที่ API ด้วยเงื่อนไขเดียว (`TicketPolicy.canSeeInternal`) ทั้งอ่านและเขียน — นักศึกษาส่ง `is_internal` ได้ 403

## 10. คนที่ 11 กดเจอปัญหาเดียวกัน → ด่วนมาก (แท็บ G + D)

- แท็บ D: จำตัวเลขบนตัวกรอง **ด่วนมาก**
- แท็บ G (`s0010`): สแกน QR ของ **D2-CM-G-ELEC (ไฟฟ้าทั่วไป ส่วนกลาง D2)** → ใบนี้มีคนแจ้งแล้ว 10 คน → **เจอปัญหาเดียวกัน**
- แท็บ D: refresh → ตัวกรอง **ด่วนมาก** เพิ่ม 1 · เปิดใบ → คนเจอปัญหา 11 คน + ประวัติ "ยกเป็นด่วนมากอัตโนมัติ"

ชี้ให้ดู:
- 1 คนนับได้ครั้งเดียว (`ticket_reporters` PK) — กดซ้ำได้ 409
- `report_count > 10` → `urgent` **ครั้งเดียวต่อใบ** · audit `auto_escalate` ไม่มีผู้กด (ระบบเป็นคนยก)
- ใบส่วนกลางเปิดให้นักศึกษา **ทุกอาคาร** — `s0010` อยู่ D2 แต่ถ้าเป็นคน D1 ก็กดได้

## 11. ใบส่วนกลางที่มีคนแย้ง (แท็บ D) ⏱

คิวงาน → ตัวกรอง **มีคนแย้งว่ายังไม่หาย** → ใบลิฟต์ D1 ที่ช่างบอกว่าซ่อมเสร็จ แต่มีนักศึกษากดเจอปัญหาเดียวกันหลังจากนั้น

ชี้ให้ดู:
- `disputed_at` ถูกตั้งเมื่อมีคนกด same-issue หลัง resolved → **ระบบไม่ปิดเอง** ต้องให้ Staff ตัดสิน

## 12. สั่งรัน job ปิดอัตโนมัติ + รายงาน (แท็บ H + D)

- แท็บ H (Swagger, admin): `POST /admin/jobs/auto-close/run` → `closed_count` ≥ 2 · ใบลิฟต์ของขั้น 11 **ไม่อยู่ในรายการ**
- แท็บ D: เมนู **รายงาน** → KPI "ระบบปิดให้เมื่อครบ 3 วัน" และแท่ง "ใครเป็นคนปิดใบ" มีช่อง **ระบบปิดให้**

ชี้ให้ดู:
- ใบที่ระบบปิด: `confirmed_by = NULL`, `close_reason = auto_closed` — รายงานแยกจากใบที่มีคนยืนยันจริงได้
- endpoint นี้มีไว้เพราะตอนนำเสนอรอ 3 วันไม่ได้ — ใช้ฟังก์ชันเดียวกับ cron ไม่มีพารามิเตอร์ข้ามเงื่อนไข · staff เรียกไม่ได้ (403)
- รายงานคิดตามเวลาไทย ทุก query มี `deleted_at IS NULL`

## ถ้ามีเวลาเหลือ

- หน้า **ผู้ใช้** (admin): เปลี่ยนบทบาท / ผูกห้อง / ระงับบัญชี — ระงับช่างที่มีงานค้างไม่ได้ (409 พร้อมเลขใบ)
